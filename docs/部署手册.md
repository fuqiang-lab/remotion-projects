## 二、部署步骤

### 步骤 0 · 前置确认

| 项 | 要求 | 检查命令 |
| --- | --- | --- |
| 系统 | Windows 10/11 x64 | — |
| C 盘空间 | ≥ 8 GB（依赖 1.96 GB + 浏览器 282 MB + 产物） | `Get-PSDrive C \| Select Free` |
| 路径规范 | 工程路径**不含中文与空格** | 否则子进程偶发异常 |

> [!warning] 本机若在受限沙箱内执行
> `remotion studio` / `render` / `still` 都会报 `spawn EPERM`——那是沙箱不允许起 Chrome 子进程，**不是部署问题**。放权后重跑，别去重装依赖。

### 步骤 1 · 装 Node.js

```powershell
winget install OpenJS.NodeJS.LTS
node -v      # 期望 v24.x
npm -v
```

**验收**：`node -v` 输出 `v24.22.0` 或更高，且满足 `package.json` 的 `engines: "^20.19 || ^22.13 || >=24"`。

### 步骤 2 · 装 ffmpeg

```powershell
winget install Gyan.FFmpeg
ffmpeg -version | Select-Object -First 1
```

**验收**：能打印 `ffmpeg version 8.x`。

> ffmpeg **不参与** Remotion 内置渲染（Remotion 自带编码器），但音频归一、参考音频转换、成片验收都要用它，缺了配音流程走不下去。

### 步骤 3 · 取得工程

> [!info] 仓库地址（2026-10-31 已建）
> `git@github.com:fuqiang-lab/remotion-projects.git`
> 公开仓库：https://github.com/fuqiang-lab/remotion-projects
> 已在其中提交 4 个作品、2 套风格库、3 份文档（588 个文件 / 5.3 MB）。

**但 clone 不等于拿到全部**——公开仓库**刻意排除**了三类内容（`.gitignore`）：

| 排除项 | 原因 | clone 后缺什么 |
| --- | --- | --- |
| `References/` | 参考视频体积大（68 MB） | 无参考素材，需单独拷 |
| `input/` | 课程研修原件 | 无 PPT，需单独拷 |
| `effects/*/audio/` | 声音样本可被用来复刻你的音色 | 无参考音频与转录 |
| `public/*/vo/` | 克隆配音是你的声音 | **作品能渲染但没有声音** |

所以先判断用哪条路：

| 路径 | 适用 | 拿得到什么 |
| --- | --- | --- |
| **A · `git clone`** | 只要代码/文档，音频可重建或无所谓 | 代码 + 文档（**无声**） |
| **B · 打包迁移** | 要完整可渲染环境（含配音） | 全部内容 |
| C · `npx create-video@latest --yes --blank` | 从零开始 | 空模板 |

**动手前先对账**：

```powershell
git remote -v            # 空 = 没有远程，只能走路径 B
git ls-files | Measure-Object -Line      # 已跟踪文件数
git status --short       # 出现 effects/ styles/ public/ = 有内容未提交，clone 会丢
```

**路径 A · git clone**

```powershell
cd C:\Users\fuqia\Documents\AIWorkspace
git clone git@github.com:fuqiang-lab/remotion-projects.git Remotion-Projects
cd Remotion-Projects

# 对账：应看到 4 个作品、2 套风格、3 份文档
(Get-ChildItem effects -Directory).Count    # 4
(Get-ChildItem styles -Directory).Count     # 2
(Get-ChildItem docs -File).Count            # 3
```

克隆后若要**带声音渲染**，二选一：

- 从源机器拷回 `public\<作品>\vo\` 与 `effects\<作品>\audio\`
- 或用本机 Qwen3-TTS 重新生成（见 `.agents/skills/qwen3-tts-local/`）

**路径 B · 打包迁移（要完整环境就走这条）**

```powershell
# 用 robocopy 复制，排除可重建与体积大的目录
robocopy "C:\Users\fuqia\Documents\AIWorkspace\Remotion-Projects" `
         "D:\迁移\Remotion-Projects" /E `
         /XD node_modules out dist .git References /XF *.log

# 打包传输
```

- 目标机**能联网**：只搬源码（约 20 MB），到目标机再 `npm ci` + 首次渲染下载浏览器
- 目标机**离线**：把 `node_modules\` 一起搬，**但仅限同为 Windows x64**；跨平台不要搬（含平台相关原生二进制）

> 不要把 `References\` 打进包：参考视频通常几百 MB，且不参与渲染，按需单独拷。

**验收（两条路径通用）**：

```powershell

```

源机器与目标机**列出的 Composition 数量必须一致**（本机当前为 7 个：`MyComp`、`SmokeTest`、`DshIntro`、`SkillMechanism`、`PromptDesign`、`EditorialLightShowcase`、`DarkDeskShowcase`）。对不上就是有作品没搬过来。

### 步骤 5 · 无头浏览器缓存（关键，最容易卡）

Remotion **不调用系统 Chrome**，首次渲染时自动下载 chrome-headless-shell 到：

```
<工程根>\node_modules\.remotion\chrome-headless-shell\
```

> [!danger] 这个缓存在 node_modules 里
> 任何一次删 `node_modules` 都会连浏览器一起清掉，下次渲染要重下 282 MB。想省时间先备份整个 `node_modules\.remotion`。

**验收**：

```powershell
Get-Content node_modules\.remotion\chrome-headless-shell\VERSION
# 期望：157.0.8080.0
Test-Path node_modules\.remotion\chrome-headless-shell\win64\chrome-headless-shell-win64\chrome-headless-shell.exe
# 期望：True
```

**卡住 / 超时怎么修**（下载源是 `remotion.media`，不是 Google CDN，**不需要挂代理**）：

```powershell
Remove-Item node_modules\.remotion -Recurse -Force
npx remotion render MyComp out\probe.mp4 --frames=0-9   # 触发重新下载，看进度条
```

### 步骤 8 · 渲染配置

`remotion.config.ts` 只有 4 行，含义如下（**不要随意加项**）：

```ts
Config.setRspack(true);                 // Rspack 打包，比 webpack 快
Config.setVideoImageFormat("jpeg");     // 中间帧用 jpeg，体积小速度快
Config.setOverwriteOutput(true);        // 同名输出直接覆盖 ← 渲染前务必确认路径
Config.setDefaultPremountInSeconds(2);  // 默认预挂载 2s，减少音画起播抖动
```

> [!warning] 覆盖输出是开着的
> 渲染前先看清 `out\<name>.mp4` 是不是你要覆盖的那个文件。

### 步骤 10 · 工作区目录结构（部署后应有的样子）

工程根目录 `<工程根>` 部署完成后必须长这样，缺哪个目录就补建（`New-Item -ItemType Directory -Force <路径>`）：

```
<工程根>\
├─ input\                 ★ 你的原始素材（PPT / Word / PDF / 图片）——只进不出
├─ References\            ★ 参考视频（学风格用，只读，不参与渲染，已被 .gitignore）
├─ public\                ★ 渲染时要读的静态资源（staticFile 引用）
│   └─ <作品名>\
│       └─ vo\            该作品的配音 mp3
├─ effects\               ★ 所有作品都在这里，一个作品一个目录
│   └─ <作品名>\
│       ├─ index.tsx      作品主组件
│       ├─ narration.ts   口播稿（单一事实来源）
│       └─ scenes\        分屏场景
├─ styles\                ★ 风格库：每个风格一套 theme.ts + ui.tsx + README
├─ src\                   脚手架：只改 Root.tsx 做注册
├─ out\                   成片与临时帧（.gitignore）
├─ docs\                  文档（本手册、通用方案、使用指导书）
└─ node_modules\          依赖 + .remotion 里的无头浏览器
```

各目录的**读写约定**：

| 目录 | 谁放 | 会被渲染读到吗 | 进 git 吗 |
| --- | --- | --- | --- |
| `input/` | 用户放原始材料 | ❌ | ✅（建议大文件不入库） |
| `References/` | 用户放参考视频 | ❌ | ❌ 已忽略 |
| `public/<作品>/` | Agent 生成的配音等 | ✅ 用 `staticFile()` | ✅ |
| `effects/<作品>/` | Agent 写代码 | ✅ | ✅ |
| `styles/` | Agent 沉淀风格 | ✅ | ✅ |
| `out/` | 渲染产物 | ❌ | ❌ 已忽略 |

> [!important] 两个最容易搞混的目录
> - **`References/` 不是 `public/`**：参考视频只给人和 Agent "看"，要给画面用必须先拷进 `public/` 并 `staticFile()`。
> - **`input/` 是原材料区**：放 PPT/文档，Agent 从里面取内容写稿，不要直接当渲染资源。

### 步骤 12 · 制作第一个测试教学动画

**目的**：用一个不依赖任何素材的 9 秒小片子，验证「打包 → 出帧 → 编码」整条链路。部署完必须做这一步，否则无从判断环境是否真通了。

工程里**已内置** `effects/smoke-test/index.tsx`（Composition id = `SmokeTest`，270 帧 / 9 秒）：

```powershell
# 12.1 三帧快检（开局 / 列表 / 收尾）
npx remotion still SmokeTest out\smoke\f040.png --frame=40
npx remotion still SmokeTest out\smoke\f140.png --frame=140
npx remotion still SmokeTest out\smoke\f235.png --frame=235

# 12.2 整片
npx remotion render SmokeTest out\smoke\smoke-test.mp4

# 12.3 验收：应为 270 帧 / 9.000 秒 / 1280x720 / 30fps
ffprobe -v error -show_entries format=duration:stream=width,height,r_frame_rate,nb_frames -of default=nw=1 out\smoke\smoke-test.mp4
```

内容长这样：开场标题「测试教学动画」→ 三条验证要点依次滑入 → 对勾「部署成功」。三屏都做了首尾淡化，**没有外链图片/音频**，所以在任何新机器上都能直接跑。

**如果你想自己另建一个**（而不是用内置的）：

1. 新建 `effects/<作品名>/index.tsx`，export 一个 React 组件
2. 在 `src/Root.tsx` 里 `import` 并注册 `<Composition id="..." component={...} durationInFrames={...} fps={30} width={1280} height={720} />`
3. `npm run lint` 通过
4. 渲三帧看版式，再渲整片

> [!warning] 为什么冒烟测试不用 emoji
> 无头浏览器常缺 emoji 字体，`✅` 会渲染成方框。自查动画里的符号一律用 **SVG 画**，别依赖系统字体。

### 工程结构

```
├─ src/index.ts        入口 registerRoot，基本不动
├─ src/Root.tsx        ★ 所有 Composition 的注册处
├─ effects/            ★ 新动画全在这里开发：effects/<作品名>/index.tsx
├─ styles/             ★ 风格库：theme.ts + ui.tsx + README
├─ public/             staticFile 资源根
├─ References/         参考素材，只读，不进 public/
├─ out/  dist/         产物
└─ docs/               文档（含本手册的项目内副本）
```

**两条硬约束**：① 新动画只能放 `effects/`，`src/Root.tsx` 只做注册；② 默认只预览不渲染，明说「渲染/导出/给 MP4」才执行 render。

## 四、渲染与验收

### 先渲样本，再渲整片

```powershell
npx remotion render SkillMechanism out\out.sample.mp4 --frames=0-299   # 10 秒样本
npx remotion render SkillMechanism out\Skill机制与安装-解说.mp4          # 整片
```

### 每次渲染前必做（TEMP 坑）

系统 TEMP 不可写时 ffmpeg 报 `...pre-encode.mp4: Permission denied`：

```powershell
New-Item -ItemType Directory -Force -Path out\.tmp | Out-Null
$env:TEMP = (Resolve-Path "out\.tmp").Path; $env:TMP = $env:TEMP
```

> 单个 `still` 静帧不走 ffmpeg 合成，通常不需要设 TEMP。

### 成片三项验收（缺一不可）

| 项 | 命令 | 达标 |
| --- | --- | --- |
| 时长 | `ffprobe -v error -show_entries format=duration -of default=nw=1 out\xx.mp4` | 与「音频秒数 + 出入场」推算值一致 |
| 电平 | `ffmpeg -hide_banner -i out\xx.mp4 -af volumedetect -f null NUL 2>&1 \| Select-String "mean_volume\|max_volume"` | `mean ≈ -16 ~ -17 dB`，`max ≈ -1.8 dB` |
| 静音 | 同上，或 `silencedetect` | 无异常长空白 |

## 五、排障表

### 部署 / 依赖

| 现象 | 原因 | 做法 |
| --- | --- | --- |
| `npm ci` 报 `EBADENGINE` | Node 低于 `engines` | 升到 Node ≥ 24 |
| `npm ci` 卡下载 | npmmirror 偶发限速 | 重试；确认 `npm config get registry` 是 npmmirror |
| 报找不到浏览器 / 下载超时 | `node_modules/.remotion` 缺失或半成品 | 删该目录，跑 `render --frames=0-9` 触发重下 |

### 运行 / 渲染

| 现象 | 原因 | 做法 |
| --- | --- | --- |
| `spawn EPERM` | 沙箱不允许起 Chrome 子进程 | 放权后重跑，别改代码别重装 |
| `pre-encode.mp4: Permission denied` | 系统 TEMP 不可写 | 按上节把 TEMP 指到 `out\.tmp` |
| 整片渲染报错但单帧正常 | 单帧不走 ffmpeg 合成 | 先 `--frames=0-299` 渲 10 秒样本定位 |
| `lint` 因未使用 import 失败 | `noUnusedLocals: true` | 删多余 import，**别放宽 tsconfig** |
| 端口 3000 被占 | 上次 Studio 没退 | 关旧进程，或 `remotion studio --port 3001` |

### 配音

| 现象 | 原因 | 做法 |
| --- | --- | --- |
| `required: -rt/--ref-text` | 即使加 `-x` 该参数仍必填 | 传占位文本 |
| 耗时失控（>1 小时） | 逐句起新进程，每句冷启动 | ≥3 句写批处理脚本，加载一次 + prompt 复用；实测逐句 3–4 分钟/句 |
| 句间音量忽大忽小 | TTS 电平随机，差可达 6 dB | 全部 loudnorm 到 -16 LUFS 再验收 |
| 终端中文乱码 | Windows 控制台 GBK | 脚本写 UTF-8 文件，再 `Get-Content -Encoding UTF8` |

### 排查顺序

1. `node -v` / `npm ls --depth=0` —— 环境是否被改动
2. `Test-Path node_modules\.remotion\chrome-headless-shell\VERSION` —— 浏览器缓存还在不在
3. `npm run lint` —— 代码问题还是环境问题
4. 渲 10 帧 `--frames=0-9` —— 最小可复现
5. 再查上面三张表

## 七、维护约定

- **版本一致**：`@remotion/*` 永远同版本，升级走 `remotion-upgrade` skill，不单独升某个包。
- **不批量读写 `node_modules`**：5.4 万文件 / 1.96 GB，任何递归搜索都会拖死会话。
- **同步两处**：工程内 `docs/部署手册.md` 与 `AGENTS.md` 的环境段，改一处要改另一处。
- `package.json` 里 `"allowScripts": { "esbuild": false }` 是有意设置，别为了装依赖放开。
