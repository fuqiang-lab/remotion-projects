# Remotion 通用部署方案（跨平台 · Agent 执行版）

> **本文写给 Agent 读**，用于在一台**陌生电脑**上从零部署 Remotion 并验证可用。
> 人类读者可当检查表用。
>
> - 阅读顺序：**先看下面的门槛速判 → 再不满足就停 → 满足才往下走部署流程**
> - 版本基线：Remotion 4.0.536 / Node 24 / 无头浏览器 157（其他版本按同样流程，以 `package.json` 为准）
> - 文中 `[MEASURED]` = 本机实测；`[OFFICIAL]` = Remotion 官方文档；`[ESTIMATE]` = 工程估算，需按实测校准
> - 关联笔记：[[05-软件开发/Remotion视频制作/部署手册-Remotion]]（本机 Windows 专项记录）

## 最低门槛速判（30 秒，不满足就别开始装）

| 必须满足 | 门槛 | 不满足的后果 |
| --- | --- | --- |
| 操作系统 | Windows x64 / macOS **15+** / Linux（libc **≥ 2.35**） | 装不上，官方不支持 |
| **排除** | Alpine Linux、nixOS、macOS 15 以下 | 直接不可用，换机或用容器 |
| CPU | **≥ 2 核** | 出帧极慢，并发只能 1 |
| 内存 | **≥ 4 GB**（推荐 8–16 GB） | 渲染被 OOM kill |
| 可用磁盘 | **≥ 10 GB**（推荐 20 GB） | `npm ci` 或中间帧写满盘 |
| Node.js | 满足工程 `engines`（现行模板 `^20.19 \|\| ^22.13 \|\| >=24`） | `EBADENGINE` |
| 显卡 | **不需要**（加 GPU 对普通 2D 内容不会更快，见 §1.4） | — |

> 只要渲染不要求"快"，2 核 / 4 GB / 10 GB 就能跑通**最低可跑档**。详细分档与依据见 §1。

## 零、Agent 使用约定（动手前必读）

1. **不许跳步**。每个阶段都有 `PASS` 判据，判据不满足就停在该阶段修，不要带病往下装。
2. **先探测再安装**。已装且满足的组件一律跳过，**禁止重复安装/降级**。
3. **区分"环境问题"与"代码问题"**。出现 `spawn EPERM`（沙箱禁止起子进程）不是代码问题，**不要改代码、不要重装依赖**（见 §5.1）。
4. **不改工程业务代码**。部署只允许动：环境、依赖、`remotion.config.ts` 的渲染默认项、`out/` 产物目录。
5. **所有命令都要能拿到退出码/输出**。禁止"看起来成功了"就宣告完成，必须贴出验收命令的实际输出。

### 0.1 交钥匙执行协议（Turnkey Protocol）

本方案按**交钥匙**执行：用户只说"给我装个 Remotion"，Agent 就要一路做到"能出片 + 有使用指导书"，中间**只在问工作区位置时停一次**。

```
① 询问工作区位置（唯一必须问用户的事）
   ↓ 用户答复
② 建工作区目录结构
   ↓
③ 探测环境 → 缺什么装什么（不问，直接装，装完报告）
   ↓
④ 部署 → 首个测试动画 → 渲染验证
   ↓
⑤ 不通过就修，回到 ③/④ 循环，直到 §7 清单全绿
   ↓
⑥ 交付：环境台账 + 验收输出 + 《使用指导书》
```

**六个关卡，缺一不算完成**：依赖装齐 → 能打包 → 能出单帧 → 能出整片 → 时长帧率对 → 有使用指导书。

### 0.2 必须先问用户：工作区放哪里

**这是唯一需要打断用户的环节**，其余全部自主完成。开工前用提问工具问一次，给出带默认值的选项：

| 选项 | 建议路径 | 适用 |
| --- | --- | --- |
| 默认（推荐） | Windows `<用户目录>\Documents\AIWorkspace\Remotion-Projects`<br>macOS `~/Documents/AIWorkspace/Remotion-Projects`<br>Linux `~/AIWorkspace/Remotion-Projects` | 绝大多数情况 |
| 非系统盘 | Windows `D:\AIWorkspace\Remotion-Projects` | C 盘紧张（依赖占 2.3 GB + 产物） |
| 自定义 | 用户指定 | 用户已有归档习惯时 |

**问法模板**：

> Remotion 工作区准备放在哪里？默认建议 `<默认路径>`（约占 2.5 GB）。
> 你可以直接回车用默认，或告诉我别的目录。

**硬性约束**（拿到答复后先校验，不合规就要求换）：

- 路径**不能含中文、空格、特殊符号**（`&`、`(`、`!` 都会让子进程出错）
- 目标盘**剩余 ≥ 10 GB**
- 不要放在 `Program Files`、`C:\Windows` 等受保护目录

### 0.3 依赖缺失：主动装，不要问

判定为"缺"就直接安装，**装完在交付报告里写明装了什么、什么版本**。只有以下三种情况才需要回头问用户：

| 情况 | 处理 |
| --- | --- |
| 需要管理员权限（`sudo` / UAC） | 说明原因并请求授权，不要静默失败 |
| 需要重启系统 | 告知用户重启后继续 |
| 安装会改变用户的既有环境（升级 Node 主版本、换包管理器） | 先说明影响再动手 |

**明确不要擅自做的事**：不要装 `tailwindcss` / `three` / `lottie-web` 等工程未声明的库；不要改全局 npm 镜像以外的配置；不要动用户的 git 历史。

### 0.4 测试循环：跑到通过为止

```
跑 §7 验收 → 有失败项？
   否 → 交付
   是 → 按 §5 决策树定位
        ├─ 环境类（缺库/缺 Node/无浏览器）→ 修环境 → 回验收
        ├─ 配置类（TEMP 不可写/端口占用）→ 改配置 → 回验收
        └─ 环境限制类（spawn EPERM 等）→ 报告用户，请求放宽权限，不要改代码硬绕
```

**循环上限**：同一失败项连续 3 轮修不好，停止并报告"卡在哪一项、已试过什么、需要用户做什么"，不要无限重试。

## 一、最低硬件要求

> 判定顺序：先看 §1.1 的**最低档**能不能满足；不满足就直接告知用户"跑不动"，不要开始装。
> 渲染是 **N 个无头 Chrome 标签页并行出帧**，所以吃的是 **CPU 核数 + 内存**，跟显卡关系不大。

### 1.1 三档配置

| 档位 | CPU | 内存 | 可用磁盘 | 适用场景 |
| --- | --- | --- | --- | --- |
| **最低可跑** | 2 核 | **4 GB** | **10 GB** | 720p、短片（<1 分钟）、只做 Studio 预览和单帧 |
| **推荐** | 4–8 核 | **8–16 GB** | **20 GB** | 1080p / 1280×720 教学片，1–5 分钟，常规交付 |
| **产线批量** | 16 核+ | 32 GB+ | 50 GB+ | 多条片连渲、长片、并行多工程 |

其余要求：

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 显卡 | **不需要** | 渲染靠 CPU 出帧；GPU 仅在 Linux 上可选加速（见 §3.5） |
| 显示器 | **不需要** | 全新无头（headless）渲染，服务器可装 |
| 网络 | 首次部署需要 | 装依赖 + 首次下载浏览器约 **300 MB**；之后可离线（见 §4） |
| 权限 | 可写工程目录 + 可写临时目录 | 临时目录不可写会直接让渲染失败（§5.2） |

### 1.2 这些数字的依据

| 结论 | 依据 |
| --- | --- |
| 核数决定并行度 | 默认并发 = `min(8, max(1, 核数/2))`，即 2 核→1 路、8 核→4 路、32 核→**顶到 8 路上限** `[OFFICIAL 源码]`。核多到一定程度收益封顶，靠 `--concurrency` 手动调 |
| 每路并发约占 0.8–1.5 GB 内存 | 每个标签页都是一整个 Chromium 实例 `[ESTIMATE]`。4 GB 只够 1 路；要开 4 路建议 ≥ 8 GB |
| 依赖固定占 ~2.3 GB | `node_modules` 实测 54,124 文件 / **1,959 MB**，加浏览器 **282 MB** `[MEASURED]` |
| 磁盘还要留中间帧 | 中间帧落盘后再编码。jpeg 帧 1080p 约 100–200 KB/帧，30fps×60s ≈ 1800 帧 ≈ **0.3 GB**；PNG 约为其 3–5 倍 `[ESTIMATE]` |

### 1.3 硬件不达标时

| 缺什么 | 降级做法 |
| --- | --- |
| 核少、内存小 | `--concurrency=1` 串行出帧；关掉 Studio 等占内存程序 |
| 磁盘紧 | 渲染前把临时目录指到有空间的盘（`TEMP`/`TMPDIR`）；只渲 `--frames` 片段验证 |
| 完全不想被硬件卡 | 改用 Remotion Lambda / Cloud Run 云端渲染（本地只需能跑 Studio） |

### 1.4 GPU 到底有没有用（常见误判，Agent 必读）

**结论：渲染不依赖 GPU；对普通 2D 内容，加 GPU 也不会更快。** 依据：

| 事实 | 来源 |
| --- | --- |
| 默认 `--gl` 是 `null`，即不强制后端，交给 Chromium 自决 | `[OFFICIAL 源码]` |
| 无 GPU 时 Chromium 自动回退 **SwiftShader** 软件光栅，照样能出帧 | `[OFFICIAL]` |
| 仅 Lambda 环境才主动加 `--disable-gpu-rasterization`（修条带 bug） | `[源码]` |
| 本机 300 帧 720p 实测：默认 11.2s / `--gl=angle` 10.7s / `--gl=egl` 10.3s | `[MEASURED]`，差异约 8%，且含约 2.6s 打包时间，属噪声 |

**GPU 真正有用的场景**（只有这两类）：

1. 画面里有 **WebGL / WebGPU / Three.js / Skia** 等 GPU 内容——软件光栅会慢一个数量级，此时必须开出 GPU（Linux 上还要 `--chrome-mode=chrome-for-testing` 才拿得到驱动）。
2. **4K 及以上**分辨率、或大量模糊/滤镜/高分辨率位图合成，光栅化成为瓶颈时。

**`--hardware-acceleration` 是编码加速，不是出帧加速**（默认 `disable`）：

| 平台 | 映射到的编码器 | 可用性 |
| --- | --- | --- |
| macOS | `h264_videotoolbox` / `hevc_videotoolbox` | Apple 芯片/Intel Mac 可用 |
| Windows / Linux | `h264_nvenc` / `hevc_nvenc` | **只有 NVIDIA 显卡可用** |
| AMD / Intel 显卡 | 无对应编码器 | **不可用** |

> [!warning] `if-possible` 不会优雅回退
> 本机（AMD 核显）实测 `--hardware-acceleration=if-possible` 直接**失败退出**，报 `[h264_nvenc] Cannot load nvcuda.dll`，并未退回到 `libx264` 软件编码。
> 所以：**非 NVIDIA / 非 Apple 芯片的机器，绝对不要加这个参数。**

**提速性价比排序**（同一机器上）：

```
并发（核数 / --concurrency）  >  编码器与 preset  >  磁盘 I/O  >  GPU
```

短平内容（<1 分钟、无 GPU 特效）的瓶颈几乎全在"每帧的样式计算 + 截图 + 编码"，加显卡收益可忽略；要快就加核数或提高并发。

> [!important] 只做预览、不渲染的话
> 最低档可再降到 **2 核 / 4 GB / 5 GB 磁盘**：Studio 只起一个开发服务器 + 一个预览标签页，不出整片。

## 二、支持矩阵（先判断"能不能装"）

### 2.1 支持的操作系统 `[OFFICIAL]`

| 系统 | 支持情况 | 附加条件 |
| --- | --- | --- |
| Windows x64 | ✅ | 无额外系统库 |
| macOS x64 / Apple Silicon | ✅ | **macOS 15 (Sequoia) 及以上** |
| Linux x64 / arm64 | ✅ | **libc ≥ 2.35** + 安装 §3.2 的共享库 |

### 2.2 明确不支持

| 环境 | 结论 | 原因 |
| --- | --- | --- |
| **Alpine Linux** | ❌ 不支持 | libc 符号不兼容 |
| **nixOS** | ❌ 不支持 | Remotion 自带 Chrome/FFmpeg 二进制，与不可变发行版架构冲突 |
| macOS 15 以下 | ❌ 不支持 | 官方明确不再支持 |
| libc < 2.35 的老发行版 | ❌ 不支持 | 需升级系统或用容器跑新基础镜像 |

### 2.3 三条"先否决"检查（不通过就别装了）

```bash
# ① 系统与架构
uname -a                      # macOS / Linux
# Windows: Get-CimInstance Win32_OperatingSystem | Select Caption,OSArchitecture

# ② Linux 的 libc 版本（必须 >= 2.35）
ldd --version | head -1

# ③ macOS 版本（必须 >= 15）
sw_vers -productVersion
```

**PASS**：三项都满足 → 进 §3。任一不满足 → 直接报告用户，建议换机 / 升级 / 用容器。

## 三、部署流程

> 通用约定：`<PROJECT_ROOT>` 指工程目录；命令按平台分组给出。
> 每个阶段结束都有 **PASS**，不满足就停。

### 阶段 0 · 环境探测（先摸清家底）

目的：避免重复安装、避免版本冲突。**探测结果记成一张台账**，后面每步都先查台账。

```bash
node -v            # 期望 >= 20.19（工程 engines 要求 ^20.19 || ^22.13 || >=24）
npm -v
git --version
ffmpeg -version    # 仅配音/验收流程需要，渲染本身不依赖
nproc              # Linux 核数；macOS: sysctl -n hw.ncpu；Windows: $env:NUMBER_OF_PROCESSORS
```

内存与磁盘：

| 平台 | 内存 | 磁盘 |
| --- | --- | --- |
| Linux | `free -h` | `df -h <PROJECT_ROOT>` |
| macOS | `sysctl -n hw.memsize` | `df -h <PROJECT_ROOT>` |
| Windows | `(Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory/1GB` | `Get-PSDrive C \| Select Free` |

**PASS**：Node / npm 存在；核数与内存、磁盘 ≥ §1.1 最低档。

> [!tip] Node 版本策略
> Remotion 官方最低 **Node 16** `[OFFICIAL]`，但现行模板的 `engines` 是 **`^20.19 || ^22.13 || >=24`**。**以工程的 `package.json > engines` 为准**，冲突时按 engines 装。

### 阶段 1 · 安装 Node.js（缺才装）

| 平台 | 命令 |
| --- | --- |
| Windows | `winget install OpenJS.NodeJS.LTS` |
| macOS | `brew install node@22` 或 `brew install node` |
| Debian/Ubuntu | NodeSource 源安装 LTS（勿用发行版自带的老 node） |
| 任意平台通用 | 用 `fnm` / `nvm` 装 LTS，便于切版本 |

**PASS**：`node -v` 落在 `engines` 允许范围；`npm -v` 可用。

**FAIL 处理**：`EBADENGINE` = Node 不达标，升 Node，**不要用 `--force` 绕过**。

### 阶段 2 · 安装系统级依赖

**Windows**：通常无需额外安装。若装原生模块报 `node-gyp` / MSVC 缺失，装 **Visual Studio Build Tools** 的 "C++ 生成工具"。

**macOS**：装命令行工具，否则原生模块编译失败。

```bash
xcode-select --install
```

**Linux**：必须装共享库，否则浏览器起不来（报 `libnss3.so: cannot open shared object file` 之类）。

```bash
# Ubuntu 24.04 / 22.04
sudo apt-get update && sudo apt-get install -y \
  libnss3 libdbus-1-3 libatk1.0-0 libasound2t64 libxrandr2 libxkbcommon-dev \
  libxfixes3 libxcomposite1 libxdamage1 libgbm-dev libcups2 libcairo2 \
  libpango-1.0-0 libatk-bridge2.0-0
```

```bash
# Debian（注意是 libasound2，不是 libasound2t64）
sudo apt-get install -y libnss3 libdbus-1-3 libatk1.0-0 libgbm-dev libasound2 \
  libxrandr2 libxkbcommon-dev libxfixes3 libxcomposite1 libxdamage1 \
  libpango-1.0-0 libcairo2 libcups2 libatk-bridge2.0-0
```

```bash
# Amazon Linux 2023 / RHEL 系
sudo yum install -y mesa-libgbm libX11 libXrandr libdrm libXdamage libXfixes \
  libxkbcommon dbus-libs libXcomposite alsa-lib nss dbus pango cups-libs \
  at-spi2-core atk at-spi2-atk
```

**PASS**：`ldd --version | head -1` ≥ 2.35；依赖包安装无报错；后续阶段 5 能成功起浏览器。

> [!warning] 容器里部署
> 基础镜像必须用 **glibc** 的（`node:20-bookworm` / `debian:bookworm` 之类）。**`alpine` 直接不支持**，不要试。

### 阶段 3 · 准备工程

**先判定搬运路径**。三条路互斥，选错会白干——最常见的事故是「clone 下来发现没有作品」。

| 路径 | 什么时候用 | 能拿到什么 |
| --- | --- | --- |
| **A · git clone** | 有可访问的远程仓库，**且作品已提交** | 仅**已提交**的内容 |
| **B · 打包迁移** | 本机仓库**没有远程**，或作品**未提交** | 完整工作区（含未提交文件） |
| **C · 全新创建** | 从零开始，不要任何既有作品 | 空模板 |

> [!danger] `git clone` 只搬"已提交"的代码
> 动手前先在**源机器**执行这两条确认：
> ```bash
> git ls-files | wc -l          # 已跟踪文件数
> git status --short | wc -l     # 未提交改动数
> ```
> 若未跟踪目录里出现 `effects/`、`styles/`、`public/`，**说明作品根本没进仓库**——
> 此时 clone 只会得到空模板，必须走路径 B。

**路径 A · git clone（有远程且已提交）**

```bash
git clone <REPO_URL> <PROJECT_ROOT>
cd <PROJECT_ROOT>
git log --oneline -1        # 确认拿到的是最新提交
ls effects                  # 必须有作品目录；空的就是选错了路径
```

远程地址由用户提供；**不要猜或编造 URL**，拿不到就问用户。

**路径 B · 打包迁移（无远程时唯一可靠）**

*B1：目标机能联网*（只搬源码，依赖在目标机重装，约 20 MB）

```bash
# 源机器：排除可重建与体积大的目录
tar -czf remotion-src.tgz \
  --exclude=node_modules --exclude=out --exclude=dist --exclude=.git \
  --exclude='References/*' -C <工程父目录> <工程名>
```

```powershell
# Windows 源机器（robocopy 更可靠，能排除大目录）
robocopy "<工程目录>" "<暂存目录>\Remotion-Projects" /E `
  /XD node_modules out dist .git References /XF *.log
Compress-Archive -Path "<暂存目录>\Remotion-Projects" -DestinationPath remotion-src.zip
```

*B2：目标机离线*（连 `node_modules` 一起搬，**仅限同平台同架构**）

```bash
tar -czf remotion-full.tgz --exclude=out --exclude=dist --exclude=.git -C <工程父目录> <工程名>
```

> 跨平台（Windows ↔ macOS/Linux）**不要**直接搬 `node_modules`：里面有平台相关的原生二进制。
> 跨平台时走 B1 + 目标机 `npm ci`，再单独拷 `node_modules/.remotion`（浏览器缓存）。

**路径 C · 全新创建**

```bash
npx create-video@latest --yes --blank <PROJECT_ROOT>
cd <PROJECT_ROOT>
```

**PASS（三条路径通用）**：


### 阶段 5 · 无头浏览器（首次必做，最易卡）

Remotion **不依赖系统 Chrome**：默认会先找系统 Chrome，找不到就自动下载 `chrome-headless-shell`。

**缓存位置（跨平台一致）**：`<PROJECT_ROOT>/node_modules/.remotion/chrome-headless-shell/`
> 4.0.536 实测是本工程内路径，**不随平台变**；旧版本可能放在用户级缓存目录，以实际报错路径为准。

**触发下载**（任意一条渲染命令都会触发）：

```bash

```

**PASS**：

```bash
test -f node_modules/.remotion/chrome-headless-shell/VERSION && cat node_modules/.remotion/chrome-headless-shell/VERSION
# 期望：一个版本号，如 157.0.8080.0
```

**三个可用开关**（下载失败或特殊环境时）：

| 场景 | 做法 |
| --- | --- |
| 下载慢/中断 | 删半成品 `node_modules/.remotion` 重试；下载源是 `remotion.media`，**不需要代理** |
| 已有系统 Chrome，不想再下 | `--browser-executable="/path/to/chrome"` `[OFFICIAL 选项]`；用系统 Chrome 还额外支持 H.264 编码 |
| Linux 想用 GPU | `--chrome-mode=chrome-for-testing` `[OFFICIAL 选项]`（默认 `headless-shell` 不用 GPU 驱动） |

> [!danger] 这个目录会被 `node_modules` 连坐
> 任何人执行 `rm -rf node_modules` 都会连 282 MB 浏览器一起清掉。**迁移/离线部署时优先备份 `node_modules/.remotion`**（见 §4）。

### 阶段 9 · 制作第一个测试教学动画

**目的**：用一个不依赖任何素材的小片子验证"打包 → 出帧 → 编码"全链路。**没有这一步，环境是否真通无从判断。**

```bash
npx remotion still SmokeTest out/smoke/f140.png --frame=140

  -of default=nw=1 out/smoke/smoke-test.mp4
```

**期望输出**：`nb_frames=270`、`duration=9.000000`、`30/1`、`1280x720`。

> [!warning] 两个必须遵守的细节
> - **不要用 emoji** 做图形（无头浏览器缺 emoji 字体，会渲染成方框），用 SVG 画。
> - **不要引用外部图片/音频** 做冒烟测试，否则新机器上必然失败，无法区分是环境问题还是素材问题。

## 四、离线 / 受限网络部署

适用：内网机、无外网、下载源被墙。

**核心思路：把"能上网的机器"上已经验证好的两样东西搬过去。**

| 搬什么 | 说明 |
| --- | --- |
| `node_modules/` 整个目录 | 含 63 个 `@remotion/*` 与全部依赖，约 1.96 GB |
| `node_modules/.remotion/` | 含已下载的 `chrome-headless-shell`，约 282 MB（**在上一条里面**，别被清掉） |

步骤：

1. 联网机器上先跑通 §3 阶段 7 的验收，**确认可用**再打包
2. 打包 `node_modules`（注意保留 `.remotion` 隐藏子目录）

## 五、故障决策树

### 5.1 第一步：先定性

| 症状 | 定性 | 动作 |
| --- | --- | --- |
| `spawn EPERM` / `EACCES` 起进程失败 | **执行环境限制**（沙箱/权限），不是代码问题 | 换有权限的环境或放权重跑。**禁止**改代码、重装依赖 |
| 找不到 `libnss3.so` 等 `.so` | Linux 系统库缺失 | 回 §3 阶段 2 装库 |
| `EBADENGINE` | Node 版本不达标 | 回阶段 1 |
| `UNMET DEPENDENCY` | 依赖没装全 | 回阶段 4，`npm ci` 重来 |
| 浏览器下载失败 | 网络 / 半成品缓存 | 删 `node_modules/.remotion` 重试，或改 `--browser-executable` |
| 渲染中途失败但 `still` 正常 | 编码/合成阶段问题 | 见 §5.2 |

### 5.2 第二步：按现象查表

| 现象 | 原因 | 做法 |
| --- | --- | --- |
| `Error opening output ...pre-encode.mp4: Permission denied` | 系统临时目录不可写 | 把临时目录指到工程内可写目录（见下） |
| 渲染极慢 | 并发过低 或 磁盘慢 | 调 `--concurrency`（默认 `min(8,核数/2)`）；换 SSD；缩短片长 |
| 渲染报内存不足 / 进程被杀 | 并发过高 | 降 `--concurrency=1` 或 `2` |
| Linux 上浏览器起不来 / GL 报错 | GPU/EGL 驱动问题 | 试 `--gl=swangle`（软件渲染兜底）。`--gl` 合法值：`swangle` / `angle` / `angle-egl` / `egl` / `swiftshader` / `vulkan`；配合 `--chrome-mode=chrome-for-testing` 才用得上 GPU |
| 加了 `--hardware-acceleration` 反而失败 | 该机器没有对应硬件编码器（AMD/Intel 无 NVENC，Windows/Linux 只认 NVENC） | 去掉该参数，用默认 `disable`（软件 `libx264`）。见 §1.4 |
| 输出视频无声音 | 音频未挂载 / 编码参数 | 检查 `<Audio>` 是否在 `Sequence` 内；先渲 `--frames=0-299` 片段验证 |
| 中文路径/文件名报错 | 路径含非 ASCII 或空格 | 工程挪到纯 ASCII 路径 |
| Windows 长路径报错 | 路径超 260 字符 | 开启长路径支持，或缩短工程路径 |

**临时目录怎么改**（跨平台差异就在这，务必分清）：

```bash
# Linux / macOS
export TMPDIR="<PROJECT_ROOT>/out/.tmp" && mkdir -p "$TMPDIR"
```

```powershell
# Windows PowerShell
New-Item -ItemType Directory -Force -Path out\.tmp | Out-Null
$env:TEMP = (Resolve-Path "out\.tmp").Path; $env:TMP = $env:TEMP
```

### 5.3 收口判断

| 检查 | 含义 |
| --- | --- |
| `npx remotion compositions` 能跑 | 打包链路 OK |
| `still` 单帧 OK 但 `render` 失败 | 问题在 **编码/合成**，不在渲染 |
| `render --frames=0-9` OK 但整片失败 | 问题在 **时长/内存/磁盘**（长片才暴露） |
| Studio 能开但渲染失败 | 问题在 **无头浏览器**（Studio 用普通浏览器） |

## 六、Agent 执行硬规则

1. **缺什么装什么**：Node、ffmpeg、系统库、无头浏览器等**必需依赖**，判定缺失就直接装，不要反复问用户（装完报告版本）。但**不要**顺手装工程未声明的业务库：`tailwindcss` / `three` / `lottie-web` 等。
2. **只在问工作区位置时打断用户**：其余环节自主推进；需要管理员权限或重启时才回头请示。
3. **不改业务代码**：部署阶段只允许改环境、依赖、`remotion.config.ts` 渲染默认项、`out/`；要改作品源码先问用户。
4. **不动 git 历史**：不 `commit` / 不 `push` / 不 `reset`，除非用户明确要求。
5. **不动版本一致性**：`@remotion/*` 同版本是红线，升级走 `remotion-upgrade` skill。
6. **覆盖输出先确认**：`setOverwriteOutput(true)` 的工程，渲染前核对输出路径，别覆盖用户成片。
7. **不谎报成功**：没有实际跑过验收命令，不要说"部署完成"；必须贴出 `ffprobe` 的实际数值。
8. **默认只预览不渲染**：用户说"做个视频"= 起 Studio 给人看；只有明说"渲染/导出/给 MP4"才 `render`。
9. **交付必须带指导书**：没有《使用指导书》的部署不算完成。
